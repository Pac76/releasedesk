# RD-005 — Work items, filters, and live dashboard

## Task brief

Complete the core product with owner/project-scoped work-item CRUD, allowlisted URL filters, quick status changes, date-only overdue behavior, and a dashboard derived entirely from authenticated owner data. Every mutation required item, project, and owner filters in addition to RLS.

## Develop handoff — initial implementation

Develop added the protected project-detail route, validated work-item actions, responsive CRUD/filter/status UI, project links, and a real dashboard. Project and work-item detail reads run in parallel; six count queries and one active-work query start independently and resolve through `Promise.all`. Initial checks passed with 92 tests.

## Testing review round 1

**REJECTED.**

Testing found a MAJOR date-boundary defect: operational “today” used `toISOString().slice(0, 10)`, which is the UTC calendar date. From 21:00 onward in Buenos Aires, work due on the still-current local day was incorrectly marked and counted as overdue. Existing tests asserted the faulty UTC behavior and missed the rollover.

No commit or deployment occurred. The Orchestrator recorded a product decision that ReleaseDesk uses `America/Argentina/Buenos_Aires` as its operational calendar timezone while storing date-only values as canonical `YYYY-MM-DD` strings.

## Develop correction

Develop replaced UTC slicing with `Intl.DateTimeFormat.formatToParts()` in the exact operational timezone. Both project-detail overdue rendering and the dashboard overdue query use the shared corrected helper. Deterministic tests cover the transition immediately before and at `03:00:00Z`, the original reproduction, lexical comparison, and exclusion of `ready` work. The suite increased to 94 tests.

## Testing review round 2

**APPROVED.**

Testing independently verified that part selection is locale-order independent, both consumers share the corrected helper, database date strings remain canonical, and display formatting pins UTC to avoid shifting the shown date. All broader authorization, filters, query parallelism, UI, and mutation criteria remained satisfied. No BLOCKER, MAJOR, or MINOR findings remained.

Remote authenticated CRUD, cross-account attempts, and hosted dashboard counts were not executed because they require the external migration/user setup. Browser control remained unavailable; UI review used source, CSS, component tests, build, and HTTP behavior.

## Orchestrator verification

The Orchestrator inspected the work-item actions, project/detail boundaries, dashboard query construction, shared date logic, and React client boundaries. Create independently proves project ownership; update/delete/status use item, project, and verified owner filters; dashboard reads are owner-scoped and launched before a single `Promise.all` await.
