# RD-007 — Repository intelligence vertical slice

## Orchestrator task brief

### User-facing outcome

A signed-in ReleaseDesk owner can connect a public GitHub repository to one of their projects, synchronize current repository health, and see an evidence-backed release-readiness verdict based on a persisted snapshot.

### Scope

- Extend the product specification and database contract for repository intelligence.
- Add a versioned Supabase migration for a normalized project repository identifier and immutable owner-scoped repository snapshots.
- Add least-privilege grants, RLS, ownership policies, indexes, constraints, and matching database types/tests.
- Add a server-only GitHub REST client for public repositories with explicit error mapping and optional server-side `GITHUB_TOKEN` support.
- Validate `owner/repository` input and verify authenticated project ownership before every sync.
- Persist a snapshot only after the complete upstream read succeeds.
- Add a deterministic readiness policy with Spanish evidence copy.
- Add an accessible project-page connection/sync form and latest-health presentation with loading/error/success states.
- Reposition the public product and README as a project-operations control plane, removing stale assessment/deployment claims.
- Add focused unit/component/contract tests and keep all existing journeys green.

### Out of scope

- GitHub OAuth or GitHub App installation.
- Private repository access.
- Background jobs, webhooks, scheduled sync, or realtime updates.
- Vercel deployment correlation.
- AI-generated summaries or recommendations.
- Multiple repositories per project.

### Observable acceptance criteria

1. An authenticated owner can submit a normalized public `owner/repository` value from the project page and synchronize it.
2. Invalid identifiers, missing repositories, rate limits, and upstream failures produce clear Spanish feedback without leaking secrets.
3. Sync reads repository metadata, default-branch head, latest workflow run, open PR count, and open issue count from GitHub and persists one immutable snapshot atomically from the application perspective.
4. Cross-user project or snapshot access is denied in server logic and PostgreSQL RLS; `anon` has no table access.
5. The project page renders the repository link, head SHA/time, workflow signal, PR/issues counts, captured time, verdict, and evidence.
6. The readiness policy is deterministic and independently unit tested for ready, at-risk, blocked, and unknown states.
7. Existing project/work-item behavior remains compatible, and lint, typecheck, tests, and production build pass.
8. README and product copy present ReleaseDesk as an actively developed project-operations product rather than an assessment handoff or generic task manager.

## Testing verdict

### Round 1 — REJECTED

Testing found three material verification problems:

1. The pgTAP cross-owner insert expected foreign-key SQLSTATE `23503`, but RLS correctly rejected the unprivileged operation first with `42501`.
2. The capture RPC did not yet have executable pgTAP coverage for authenticated success, cross-owner denial, and transaction rollback.
3. Pagination rejected an exact 10,000-result boundary and its tests did not prove the boundary and fail-safe behavior.

### Round 2 — APPROVED

After correction, Testing reported no blockers, majors, or minors. Its targeted suite passed 40 tests; lint, typecheck, the full 119-test suite, production build, and diff check passed.

### Round 3 — REJECTED at the pre-push presentation gate

The implementation remained approved, but the repository was not yet ready to present:

1. Production still served the previous commit because RD-007 had not been pushed yet, so the public URL and current product documentation were temporarily out of sync.
2. Two operational files still used assessment-era language: the local Supabase project ID was `interview`, and the seed comment referred to evaluator accounts.

Testing also confirmed that local documentation links resolved, the deleted submission document had no remaining references, the public app and repository were anonymously reachable, security headers were present, and no credentials were exposed.

## Correction rounds

### Develop correction 1

- Split the RLS denial assertion (`42501`) from a privileged foreign-key integrity assertion (`23503`).
- Added pgTAP coverage for successful RPC capture, cross-owner denial without mutation, and rollback after an invalid snapshot.
- Corrected pagination so exactly 10,000 results are accepted when page 101 is empty, while genuinely unbounded responses still fail safely.
- Added focused regression tests for both pagination outcomes.

- Renamed the local Supabase project identifier to `releasedesk`.
- Replaced the remaining evaluator-specific seed comment with product-neutral demo-account language.
